# MILESTONES – משחק סיימון (Simon)

מסמך זה מחלק את מימוש המוצר לאבני דרך הניתנות לפיתוח, בדיקה ואישור בנפרד. מקורות האמת: `PRD.md` להתנהגות ולהיקף, `ARCHITECTURE.md` לפתרון הטכני, ו-`DESIGN.md` למבנה ולעיצוב, לרבות התמונות המקושרות אליו. אין להוסיף יכולות שאינן מופיעות במקורות.

## כללי ביצוע הפיתוח – Development Execution Rules

> **הנחיות מחייבות ל-AI המפתח:** יש לממש את ה-Milestones **לפי סדר הופעתם**. בסיום כל Milestone יש **לעצור**, להציג למשתמש את התוצר העובד, סיכום קצר של מה שמומש ותוצאות בדיקות מול **כל** סעיפי ה-Definition of Done (עובר/נכשל, עם הסבר אם יש מגבלה). **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**. במקרה של כשל יש לתקנו ולבדוק מחדש לפני בקשת האישור. אין לפרש אישור למילסטון אחד כאישור אוטומטי להמשך.

- לכל אורך הפיתוח: ממשק בעברית ו-RTL, Mobile-First לטלפון, שני מסכים בלבד (**בית**, **אודות**), ללא Backend, Database, Authentication או AI.
- יש להיצמד ל-React, TypeScript, Vite, CSS רגיל, `useReducer`, Web Audio API, `localStorage`, `canvas-confetti`, `vite-plugin-pwa`/Workbox, Vitest ו-React Testing Library, בהתאם לתפקידיהם במסמך הארכיטקטורה.
- בדיקות ידניות מתבצעות בדפדפן מובייל או באמולציית מובייל לפי ההתאמה. בדיקות התנהגות מערכת ההפעלה, אודיו ו-PWA במכשיר אמיתי (נעילת מסך, מצב שקט, התקנה, Offline) **מתבצעות על ידי המשתמש**; ה-AI מכין הוראות בדיקה פשוטות ואינו מציג בדיקה שלא בוצעה כאילו עברה.
- **Build ופרסום בכל אבן דרך (החל מ-Milestone 4):** כל אבן דרך מסתיימת ב-`npm run build` תקין ובגרסה חיה ועובדת ב-GitHub Pages (`https://yonisaban.github.io/SimonGame/`). הפרסום מתבצע אוטומטית על ידי ה-Workflow של GitHub Actions (לפי `ARCHITECTURE.md` סעיף 2.9) בכל Push ל-`main`, ורק לאחר אישור המשתמש ל-Push. אחרי ה-Push ה-AI מוודא שה-Workflow הצליח ושהאתר החי נטען כמשחק עובד – **לא דף לבן** – עם יכולות אבן הדרך, ומדווח על כך למשתמש; כשל מתוקן מיד.

## Milestone 1 – בסיס אפליקציה ושני מסכים מעוצבים ✅

**שם ומטרה:** הקמת פרויקט Frontend עובד ושני המסכים בעיצוב עקבי, כדי שניתן יהיה להציג ולבדוק את מבנה המוצר לפני חיבור לוגיקת המשחק.

**מה יש לממש:**
- פרויקט React + TypeScript + Vite עם CSS רגיל, בדיקות בסיסיות ופקודות `dev`, `build`, `test` ו-TypeScript typecheck. קוד המקור מנוהל ב-Git Repository `SimonGame` ב-GitHub (כבר מחובר).
- נעילת גרסאות לפי `ARCHITECTURE.md` (סעיף 2.9): גרסאות מדויקות ב-`package.json`, `package-lock.json`, `.nvmrc` ו-`engines`, ורישום הגרסאות שנבחרו כ-ADR. `base: "/SimonGame/"` ב-Vite.
- App Shell עם שני מסכים פנימיים בלבד, ניווט קבוע **"בית"** / **"אודות"**, `lang="he"` ו-RTL, ללא טעינת דף מחדש בעת מעבר. מיכל ממורכז עד 480px ורוחב מינימלי 360px.
- מבנה ה-UI לפי `DESIGN.md`: לוח Simon עגול בעל ארבעה אזורים (ירוק למעלה משמאל, אדום למעלה מימין, צהוב למטה משמאל, כחול למטה מימין) ודיסק מרכזי ריק, כותרת **"סיימון"**, חיווי שלב וכפתור **"התחל משחק"**. במסך אודות: הסבר המשחק בנוסח המחייב, אזור היסטוריה ריק וחיווי היעדר תוצאות.
- יישום השפה החזותית: Theme כהה מה-Mockups, צבעי ה-Style Guide וצבעי Background/Surface/Border שב-`DESIGN.md`, Typography מסוג Heebo עם Fallback (ארוז באפליקציה דרך `@fontsource/heebo`, ללא Google Fonts), חיווי **"שלב 1 מתוך 10"** לפני משחק, כפתורים, כרטיסים ופס ניווט; ללא כפתורי הגדרות או מתג סאונד.
- מילוי סעיף **Run commands** ב-`CLAUDE.md`.

**תוצר מצופה:** אפליקציית מובייל מקומית שניתן לפתוח ולנווט בה בין **בית** ל-**אודות**, עם מבנה ועיצוב קרובים להמחשות. בשלב זה הכפתור והלוח אינם מריצים עדיין משחק.

**Definition of Done:**
- [ ] `npm run build` ו-TypeScript typecheck מסתיימים בהצלחה; בדיקת Render/Navigation בסיסית עוברת.
- [ ] גרסאות הכלים נעולות ומתועדות; `base` הוא `/SimonGame/` והאפליקציה נפתחת בכתובת המקומית תחת הנתיב הזה.
- [ ] שני המסכים נפתחים ומעבר ביניהם אינו מרענן את הדף; אין מסך שלישי.
- [ ] מוצגים ארבעת אזורי הלוח במיקומים הנכונים, חיווי **"שלב 1 מתוך 10"** וכפתור **"התחל משחק"**; מסך אודות מציג הסבר והודעת היסטוריה ריקה.
- [ ] כל הטקסטים הגלויים בעברית, כיווניות RTL, והתצוגה נוחה וקריאה ב-Viewport של Smartphone אנכי (360px ומעלה), ללא גלילה אופקית.
- [ ] לא נוספו יכולות שאינן ב-PRD, ואין Backend או Database.

## Milestone 2 – משחק מלא: לוגיקה וממשק (ללא צליל וקונפטי) ✅

**שם ומטרה:** מימוש סבב משחק שלם בצד הלוגי והחזותי: התחלה, הצגת רצף, שחזור, התקדמות, ניצחון והפסד עם משוב חזותי.

**מה יש לממש:**
- Game Engine ו-`useReducer` עם מצבי `idle`, `presenting`, `awaitingInput`, `won`, `lost`; רצף אקראי המתחיל בצבע אחד וגדל בצבע נוסף בכל שלב, עד 10, כולל אפשרות לחזרות על צבע. הרנדום נוצר מחוץ ל-Reducer.
- Sequence Controller המציג את הרצף בקצב ובהמתנות שבטבלה ב-`DESIGN.md` עם Glow נפרד לכל צבע. קלט חסום בזמן ההצגה ופעיל רק בתור השחקן; לחיצה מתחילה ב-`pointerdown` ומאירה לפחות 300ms או כל עוד האצבע לוחצת.
- אימות סדר הלחיצות ללא הגבלת זמן: מעבר לשלב הבא רק לאחר שחזור מלא; טעות אחת מפסידה מיד; השלמת שלב 10 מנצחת. הצגת **"שלב X מתוך 10"** והנחיות הסטטוס לפי `DESIGN.md`.
- מצבי סיום: הודעת ניצחון/הפסד בנוסח המחייב ב-`DESIGN.md`, כפתור **"אישור"** שסוגר את ההודעה ומחזיר למסך הבית עם **"התחל משחק"** ו-**"שלב 1 מתוך 10"**. ציון תוצאת המשחק כמספר **השלבים שהושלמו** (0 בהפסד בשלב 1, 10 בניצחון). ללא צליל וללא קונפטי באבן דרך זו.
- ניהול Timers ו-Callbacks ניתנים לביטול (`AbortController` + `presentationId`).
- **מעבר ל"אודות" באמצע משחק – פתרון זמני עד Milestone 4:** ההשהיה וההמשך עדיין לא קיימים. באבן דרך זו, מעבר ל-**"אודות"** בזמן משחק פעיל מבטל את המשחק (עוצר הארה ו-Timers) ומחזיר את מסך הבית למצב **"לפני תחילת משחק"**, בלי לרשום תוצאה. זו התנהגות זמנית שתוחלף בהשהיה אמיתית ב-Milestone 4, ואינה נבדקת מול ה-PRD באבן דרך זו.

**תוצר מצופה:** משתמש יכול להתחיל ולסיים משחק אמיתי (בשקט, עם הארות בלבד), להפסיד או לנצח, ולפתוח משחק חדש מיד. צליל וקונפטי יתווספו ב-Milestone 3, והיסטוריה ב-Milestone 5.

**Definition of Done:**
- [ ] משחק מתחיל בלחיצה על **"התחל משחק"**; אורכי הרצף בשלבים 1, 2 ו-10 הם בהתאמה 1, 2 ו-10, ורצף קודם הוא תחילית (prefix) של הרצף הבא.
- [ ] ההארה נבדלת בין ארבעת הצבעים; קצב ההצגה וההמתנות תואמים לטבלה ב-`DESIGN.md` ואינם משתנים בין שלבים.
- [ ] לחיצות בזמן `presenting` אינן משפיעות; לחיצות נכונות מקדמות את הקלט, ולחיצה שגויה אחת גורמת להפסד ללא ניסיון נוסף.
- [ ] בדיקות מכסות הפסד בשלב 1 (0 השלמות), הפסד בשלב מתקדם, ניצחון לאחר השלמת שלב 10, מניעת שלב 11 ויצירת רצף חדש במשחק הבא (אחרי **"אישור"** ו-**"התחל משחק"**).
- [ ] בתום משחק מופיעות הודעה וכפתור **"אישור"** בנוסח הנכון; הודעת ההפסד מציגה את מספר השלבים שהושלמו.
- [ ] רענון דף מבטל משחק פעיל ומציג מצב התחלה; אין שמירת מצב משחק פעיל לאחסון מתמיד.
- [ ] מעבר ל-**"אודות"** באמצע משחק אינו משאיר הארה או Timer פעילים (לפי הפתרון הזמני שלמעלה).

## Milestone 3 – צלילים וקונפטי ✅

**שם ומטרה:** להוסיף למשחק את המשוב הקולי ואפקט הניצחון.

**מה יש לממש:**
- Audio Engine עם Web Audio API: ארבעה צלילים נבדלים (Oscillator + Gain עם Envelope קצר), וצלילי סיום נפרדים לניצחון ולהפסד. צליל נפרד לכל צבע מושמע בהצגת הרצף ובלחיצת השחקן.
- `AudioContext` נפתח או מתחדש מתוך Gesture ב-**"התחל משחק"** וב-**"המשך משחק"** בלבד. בכשל `resume()` לא מתחיל רצף שקט: מוצגת הודעה קצרה בעברית ואפשרות ניסיון חוזר מתוך Gesture.
- בלחיצה שגויה מושמע מיד צליל הצבע שנלחץ, ולאחר 1000ms מושמעים צליל ההפסד והודעת ההפסד יחד. בניצחון: 1000ms אחרי הלחיצה האחרונה מוצגים הודעת הניצחון, צליל הניצחון והקונפטי.
- קונפטי באמצעות `canvas-confetti` בניצחון בלבד; מופעל פעם אחת בכניסה ל-`won`, ונעצר ומנוקה ביציאה; תמיכה ב-`prefers-reduced-motion`.
- ביטול צלילים פעילים יחד עם ביטול ה-Timers הקיים (גם במעבר ל"אודות" לפי הפתרון הזמני).

**תוצר מצופה:** משחק מלא עם צלילים ואפקט ניצחון.

**Definition of Done:**
- [ ] ארבעת הצבעים מפיקים צלילים שונים, בהצגת הרצף ובלחיצה.
- [ ] לחיצה שגויה משמיעה מיד את צליל הצבע שנלחץ, ושנייה אחר כך את צליל ההפסד יחד עם הודעת ההפסד.
- [ ] צליל ניצחון וקונפטי מופיעים בניצחון בלבד; בהפסד אין קונפטי.
- [ ] כשל בפתיחת האודיו מציג הודעה בעברית ואינו מתקדם בשקט; ניסיון חוזר מתוך לחיצה עובד.
- [ ] מעבר ל-**"אודות"** באמצע משחק אינו משאיר צליל פעיל.
- [ ] הוראות הבדיקה כוללות בדיקה של המשתמש בטלפון אמיתי (כולל מצב שקט), והתוצאה מדווחת.

## Milestone 4 – השהיה וחידוש משחק ✅

**שם ומטרה:** לאפשר מעבר לאודות, נעילת טלפון או יציאה זמנית לאפליקציה אחרת בלי לאבד את השלב הפעיל, תוך חידוש בשליטה מפורשת של השחקן.

**מה יש לממש:**
- החלפת הפתרון הזמני של Milestone 2 (ביטול משחק במעבר ל"אודות") בהשהיה אמיתית.
- מצב `paused` ומנגנון ביטול מלא של Playback, Timers, Highlights וצלילים פעילים במעבר למסך **"אודות"** או באירועי `visibilitychange`/`pagehide` רלוונטיים.
- שימור הרצף והשלב ב-Memory בלבד; איפוס קלט חלקי של השלב הנוכחי בעת השהיה.
- חזרה למסך הבית במצב מושהה עם כפתור **"המשך משחק"**. רק לחיצה עליו תציג מחדש את הרצף **המלא** של אותו שלב ותאפשר שחזור מתחילתו; ללא Resume אוטומטי.
- טיפול בהמתנות שבין שלבים: השהיה בהן היא השהיה בשלב החדש (עם הצבע הנוסף), לפי `ARCHITECTURE.md` סעיף 2.3.
- יציאה מהמסך בזמן ההמתנה שלפני הודעת הסיום או בזמן שהיא מוצגת: ביטול הצליל, ההודעה והקונפטי וחזרה ל-`idle` ללא רישום תוצאה כפול.
- הגנה מפני Timers/Callbacks מיושנים, ריבוי Resume ולחיצות במהלך הצגת הרצף.
- **הקמת פרסום אוטומטי ל-GitHub Pages (הוקדם מ-Milestone 7):**
  - וידוא שה-Repository `SimonGame` ציבורי לפני הפריסה; אם לא – עצור והדרך את המשתמש לשנות זאת. הגדרת Pages: **Settings → Pages → Source: GitHub Actions** (המשתמש מבצע, בהדרכה).
  - Workflow של GitHub Actions (`.github/workflows/deploy.yml`) המבצע `npm ci`, typecheck, בדיקות, Build ו-Deployment אוטומטי של `dist/` אל GitHub Pages בעקבות Push ל-`main`, עם הרשאות מינימליות (`contents: read`, `pages: write`, `id-token: write`) ו-Node בגרסה הנעולה; Build שנכשל אינו נפרס. הפריסה מתבצעת רק לאחר אישור המשתמש ל-Push.
  - בדיקה מקומית לפני ה-Push: `npm run build` + `npm run preview` (`http://localhost:4173/SimonGame/`) – המשחק נטען ועובד, ללא דף לבן וללא שגיאות 404.

**תוצר מצופה:** משחק פעיל שומר על השלב שלו בזמן מעבר בין שני המסכים או בזמן הסתרת האפליקציה, וממשיך ידנית ללא שינוי ברצף. מאבן דרך זו, כל Push ל-`main` מפרסם אוטומטית גרסה עובדת ב-GitHub Pages.

**Definition of Done:**
- [ ] מעבר ל-**"אודות"** בזמן הצגת רצף ובזמן שחזורו משהה את המשחק ועוצר מיד הארה וצליל.
- [ ] חזרה ל-**"בית"** אינה מפעילה את הרצף מעצמה; הכפתור **"המשך משחק"** מופיע במשחק מושהה בלבד.
- [ ] לחיצה על **"המשך משחק"** מציגה מחדש את כל הרצף הקיים, גם אם חלק ממנו הוקש קודם; השלב אינו משתנה ואין תוספת צבע חדשה (פרט להשהיה בהמתנה שבין שלבים, שבה הצבע החדש כבר נוסף).
- [ ] הסתרת האפליקציה וחזרה אליה פועלות לפי אותו כלל השהיה/חידוש, ללא שינוי לא צפוי כתוצאה מ-Callback שבוטל.
- [ ] יציאה מהמסך בזמן ההמתנה לפני הודעת הסיום או בזמן הצגתה מחזירה ל"לפני תחילת משחק" ואינה משאירה צליל או קונפטי.
- [ ] משחק שהושהה אינו נחשב הפסד, ורענון דף עדיין מאפס את המשחק הפעיל.
- [ ] `npm run build` עובר, וה-Build המקומי (`npm run preview`) נטען כמשחק עובד ללא דף לבן.
- [ ] אחרי ה-Push, ה-Workflow ב-GitHub Actions עובר ומפרסם אוטומטית; האתר החי `https://yonisaban.github.io/SimonGame/` נטען דרך HTTPS כמשחק עובד (לא דף לבן), ללא שגיאות 404, עם יכולות Milestones 1–4.

## Milestone 5 – היסטוריית משחקים ומחיקה מאושרת ✅

**שם ומטרה:** להשלים יכולת משתמש של צפייה בעשרת המשחקים האחרונים וניהול ההיסטוריה המקומית ממסך אודות.

**מה יש לממש:**
- History Repository ב-`localStorage`, עם רשומות של תאריך ושעת סיום, מספר השלבים שהושלמו ותוצאה (`won`/`lost`); שמירת משחק בסיומו **פעם אחת בלבד**, ולא בעת השהיה/Refresh.
- שמירת עד עשרה משחקים בסדר החדש לישן, כולל הסרת הרשומה הישנה ביותר בהכנסת רשומה נוספת.
- מסך **"אודות"** מציג רשימת כרטיסי היסטוריה בפורמט שב-`DESIGN.md`, חיווי ריק כשאין רשומות וכפתור **"מחק היסטוריה"** (מוצג רק כשיש רשומות).
- Dialog לאישור מחיקה עם **"ביטול"** ו-**"מחק"**, כולל עדכון התצוגה לאחר מחיקה.
- טיפול בקריאה/כתיבה/מחיקה לא זמינים ב-`localStorage` והצגת הודעת שגיאה בעברית, בלי לחסום משחק; בדיקות להגנה מפני רישום כפול ב-React Strict Mode.
- Build ופרסום: `npm run build` + בדיקת `npm run preview`, ואחרי אישור ה-Push – פרסום אוטומטי ל-GitHub Pages ובדיקת האתר החי.

**תוצר מצופה:** לאחר סיום משחק מוצגת תוצאתו במסך אודות, נשמרת בטעינה חוזרת וניתנת למחיקה רק לאחר אישור.

**Definition of Done:**
- [ ] ניצחון או הפסד מוסיפים בדיוק רשומה אחת עם זמן סיום, מספר שלבים שהושלמו ותוצאת **"ניצחון"**/**"הפסד"** בתצוגה.
- [ ] מעבר מסכים, השהיה, Refresh של משחק פעיל או יציאה באמצעו אינם מוסיפים רשומה; יציאה בזמן הודעת הסיום אינה מוסיפה רשומה שנייה.
- [ ] אחרי 11 משחקים קיימות לכל היותר 10 רשומות, בסדר מהחדש לישן; הן נשמרות לאחר Refresh באותו אחסון מקומי.
- [ ] **"ביטול"** לא משנה נתונים; **"מחק"** לאחר אישור מרוקן היסטוריה ומחזיר חיווי ריק.
- [ ] כשל אחסון אינו מונע משחק, ומוצגת הודעה מובנת בעברית כאשר פעולת שמירה או מחיקה נכשלת.
- [ ] בדיקות אוטומטיות מאמתות היסטוריה, מגבלת עשר, מחיקה, כשל אחסון ומניעת שמירה כפולה.
- [ ] `npm run build` עובר; אחרי ה-Push האתר החי ב-GitHub Pages נטען כמשחק עובד (לא דף לבן) והיסטוריה נשמרת ומוצגת בו.

## Milestone 6 – PWA ו-Offline (בדיקה מקומית על Build) ✅

**שם ומטרה:** להפוך את המשחק השלם לאפליקציה הניתנת להתקנה ולעבודה Offline, ולאמת זאת על Build מקומי לפני הפרסום.

**מה יש לממש:**
- יצירת אייקון האפליקציה לפי הגדרת ה-App Icon ב-`DESIGN.md`: קובץ SVG מקור + PNG בגדלים 192 ו-512, Maskable, Apple Touch Icon ו-Favicon, שנשמרים ב-`public/`.
- הגדרת `vite-plugin-pwa` עם `generateSW`: Manifest (`name`/`short_name` `Simon`, `id` `/SimonGame/app`, `lang`/`dir`, `orientation: portrait`, `display: standalone`, `start_url` ו-`scope` תחת `/SimonGame/`) ו-Precache של כל נכסי האפליקציה, כולל הפונט.
- `registerType: "prompt"`: הודעת עדכון בעברית (לפי `DESIGN.md`) המוצגת רק במצב `idle`; ללא `skipWaiting`/`clientsClaim` וללא Reload כפוי בזמן משחק.
- בדיקה על `npm run build` + `npm run preview` (כתובת `http://localhost:4173/SimonGame/`): ה-Service Worker נרשם, ה-Precache מושלם, וניתוק הרשת אינו מונע פתיחה, משחק, צלילים, ניווט וצפייה בהיסטוריה.
- אחרי אישור ה-Push – פרסום אוטומטי ל-GitHub Pages ובדיקה שהאתר החי נטען כמשחק עובד וה-Service Worker נרשם בו.

**תוצר מצופה:** Build מקומי שניתן להתקין ולהפעיל גם ללא רשת.

**Definition of Done:**
- [ ] Manifest ו-Service Worker תקינים (נבדק בכלי המפתחים); האייקונים קיימים ותקינים.
- [ ] על ה-Build המקומי, אחרי טעינה ראשונה ו-Precache מוצלח, ניתוק הרשת אינו מונע טעינה מחדש, משחק מלא, צלילים, ניווט והיסטוריה שמורה.
- [ ] כל הנכסים נטענים תחת `/SimonGame/` ללא שגיאות 404.
- [ ] הודעת העדכון מופיעה רק ב-`idle`, ולעולם לא מפסיקה או מרעננת משחק פעיל.
- [ ] בדיקות Regression אוטומטיות על כל יכולות Milestones 2–5 עוברות.
- [ ] אחרי ה-Push האתר החי ב-GitHub Pages נטען כמשחק עובד (לא דף לבן), וה-Manifest וה-Service Worker תקינים בו.
